# テスト送金元を学習・検証から除いた評価

[Table 2の観測グラフを復元した97,448件の評価](README_paper.md) の10-foldを使う。各foldで外側評価グラフの送金元クラスタID集合を作り、そのIDに該当するノードを学習・内側検証の観測グラフから役割を問わず削除する。付随する辺も削除する。対象の内部メンバーを含む場合は入力不整合として停止する。

- 学習・検証・評価の対象ID、サブグラフラベル、学習更新数、モデル、乱数seedは元の評価と共通。元の学習グラフごとの件数を維持し、学習側から外部ノードを除く。
- 外側評価グラフのノード、元の43属性、役割、辺、ラベルは元の評価と同じ。学習・検証にテスト送金元のクラスタIDが残らないことを、別の役割で現れる場合も含めて各foldで照合する。
- 標準化係数は、除去後の学習グラフに現れる一意なクラスタだけで再計算する。内側検証APでcheckpointを選び、内側検証F1で閾値を決める。
- テスト送金元IDは、除去対象を決めるためにだけ用いる。この操作は各foldで独立に行う。外部の受取先など、テスト送金元に該当しないクラスタは共有され得る。

該当するサブグラフを丸ごと学習から除くと、各foldの学習件数は78,932〜78,933件から2,137〜2,271件に減るため、学習対象は維持して外部文脈だけを除去する。結果の差には、送金元の共有を断つこと、学習・検証で利用できる境界情報が減ること、標準化対象が変わることが含まれる。

送金元として一度でも現れるIDについて、全役割で同じIDを持つグラフを連結し、グループ全体を同一分割に入れる方法も調べた。最大グループは94,911件（97.4%）で、通常のサイズの10-foldを作れる分布ではなかった。[グループ規模の監査](results_funding_holdout/whole_graph_group_audit.json)

## 実行

リポジトリルートから以下を実行する。完了済みfoldは同じ出力先で再利用する。

```bash
.venv-gnn-v1/bin/python -m pytest -q -p no:cacheprovider table3_message_passing/test_smoke.py table3_message_passing/test_funding_holdout.py
.venv-gnn-v1/bin/python -u table3_message_passing/funding_holdout.py
```

結果は `results_funding_holdout/` に保存する。`fold_<nn>_audit.json` に除去前後の検証、`summary.csv` と `paired_folds.csv` に4指標の元の実験との差、各モデルのfold別ディレクトリに閾値・checkpoint・外側予測を保存する。
