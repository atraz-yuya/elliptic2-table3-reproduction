# Elliptic2 Table 3 再実装のデータ・ラベル監査

監査対象は [97,448件の再実装](README_paper.md) の保存済み40実行。結果は [データ監査JSON](results_paper/data_audit.json) に保存した。

## 原データと実際のモデル入力

| 項目 | 照合結果 |
| --- | --- |
| 原データのラベル | 公開版 `connected_components.csv` は121,810件、うちSuspicious 2,763件。モデルの対象97,448件はLicit 95,249件、Suspicious 2,199件。各IDの入力ラベルと保存予測のラベルを原本と照合した。 |
| 対象の選択 | 公式GLASS前処理の train 割当を `nodes.csv` での初出順で適用した。Table 2のクラス別件数と20個の平均・標本標準偏差が論文の表示桁まで一致した。 |
| 43属性 | 背景ノード49,299,864行を全走査した。キャッシュの737,870クラスタで欠損、重複、43属性値の相違はいずれも0件。モデルで実際に使った431,685クラスタの入力もキャッシュと一致した。 |
| 内部取引 | 背景取引196,215,606行をZIPから全走査し、同じ対象の内部にある367,137取引について、送金元ID・送金先ID・取引IDの組を重複件数込みで公開版 `edges.csv` と照合した。過不足0件。 |
| 境界キャッシュ | 全背景取引から独立に作った919,018件の境界レコードを、クラスタ・方向・相手IDの組でSQLiteと照合した。過不足0件。 |
| 学習入力の観測グラフ | 始点に入る外部辺と終点から出る外部辺を抽出して再構築した。グラフID別のノード・役割635,503件と有向辺584,929件は学習入力と完全一致した。 |
| foldと標準化 | 各foldで学習・内側検証・外側評価の対象IDは互いに素。外側評価は10foldで全対象を一度ずつ含む。学習に現れる一意なクラスタだけで43属性の標準化係数を再計算し、全40実行の保存値と一致した。 |
| 保存された予測 | 全40実行のID・ラベル、閾値判定、混同行列、AP・Precision・Recall・F1と集計表が再計算結果に一致した。 |

原本走査後、独立な境界再構築コードの初回比較で、クラスタIDの代わりに所属IDの集合を参照する誤りが見つかった。監査コードを修正し、原本との完全一致を確認済みの内部CSVと境界キャッシュのハッシュを再検証したうえで、全ノード・役割・辺を再照合した。表は修正後の照合結果である。

## ラベルとモデルが知り得る情報

- `ccLabel` は対象サブグラフごとの教師ラベル。学習グラフのラベルを損失に、内側検証ラベルをチェックポイントと閾値の選択に、外側ラベルを分割の層化と指標計算に使う。加工済み内部属性CSVの `ccLabel` 列はモデルの属性読み込み対象外。
- モデル入力は原本の43属性、内部・送金元・送金先の3役割フラグ、観測グラフの辺。役割フラグはグラフ内の位置と辺の向きから決まる。クラスタIDは属性の結合とグラフの組み立てに使う。
- 全40チェックポイントで各外側foldから両クラス64件ずつを取り、ラベルを反転しても入力特徴・辺・所属テンソルは同一だった。反転ラベルを渡した場合と、バッチのラベル欄を空にした場合の推論logitは、元のラベルの場合と完全一致した。[ラベル遮断検査](results_paper/data_audit_label_isolation.json)
- 全40チェックポイントから外側・内側予測も再生成した。保存APとの差は最大2.3×10⁻¹⁶、内側から再計算した閾値との差は最大1.8×10⁻⁷、保存閾値での外側判定変更は0件だった。[チェックポイント再評価](results_paper/data_audit_checkpoint_replay.json)
- テスト対象の内部ノードが学習グラフの参加者に出るケースは全foldで0件。テスト対象の97.21〜97.70%は少なくとも一つの外部クラスタを学習側と共有する。これは共有された背景ネットワーク内でのサブグラフ分類であり、ラベルの直接利用と区別する。[分割の監査](results_paper/split_audit.json)

## 共有する送金元が持つ予測情報

同じ10-foldで、学習側だけから各外部クラスタがSuspiciousなグラフに出た割合を推定し、テストグラフでは該当する近傍の最大値をスコアとした。割合は学習正例率を20件分加えて平滑化した。送金元だけを使ったAPは **0.8670 ± 0.0297**、送金先だけでは **0.1349 ± 0.0225**。この診断のクラスタ別スコアをGCN等の入力には使っていない。

| 外側評価グラフの送金元 | グラフ数 | 正例数 | 保存済みGCNのfold平均AP |
| --- | ---: | ---: | ---: |
| 学習側でも送金元だったクラスタが1つ以上 | 93,255 | 1,942 | 0.9514 |
| 送金元あり、全員が学習時の送金元としては未出現 | 285 | 188 | 0.8802 |
| 送金元なし | 3,908 | 69 | 0.4113 |

各群の正例率が異なるため、このAP差には対象集団の違いが含まれる。診断は、共有送金元が強い識別情報を持つことを示す。GCNがその情報をどれだけ利用したか、また論文との差の原因かは、この診断からは特定できない。[共有送金元の診断](results_paper/data_audit_shared_id_diagnostic.json)

## 論文と一致を確認できる範囲

公開版の件数、Table 2の表示精度での統計、foldの件数、公開記述の評価手順まで照合できた。著者の個別対象ID・fold割当・入力テンソル・ベースライン前処理が入手できれば、1 foldからID、属性、辺、学習設定を直接照合できる。

Elliptic2のラベルは既知の主体に結び付く取引経路を基に作られている。43属性は多くがビン化されており、列の詳細な定義や予測時点で利用可能だったかは公開情報からは確定できない。したがって、今回の監査が確認したのは正解ラベルの直接混入とデータ取り違えの有無であり、共有背景やラベル生成に由来する間接的な予測信号の有無には別の検証が要る。[Elliptic2原論文 §2.2](https://arxiv.org/abs/2404.19109) · [Buu & Kim §4.1](https://doi.org/10.3390/math14213924)
